# Activation de KORA Colis interurbain

1. Appliquer les migrations applicatives et synchroniser les permissions avec `php artisan db:seed --class=KoraBusRolePermissionSeeder --no-interaction`.
2. Dans le contrat OPS `/parcels/data`, habiliter un hub pour chaque agence interne et arrêt. Un point partenaire se configure avec `kora_point_uuid` (jamais avec `agency_uuid`) : le hub prend le type `partner_point` et hérite de l’agence partenaire du KORA POINT. Un hub archivé est retiré des listes publiques mais conserve les colis existants. Créer le corridor orienté avec `enabled=false`. Créer une règle fiscale Colis active par pays d’encaissement avec le code pays comme portée, puis publier un tarif. Le CDC donne 1 500 XOF pour Cotonou–Parakou, 2 000 XOF pour Cotonou–Lomé et 6 000 XOF pour Cotonou–Abidjan, avec 1 500 XOF par tranche supplémentaire de 5 kg et un maximum de 30 kg. Renseigner le tarif de retour approuvé par Finance. Le connecteur fiscal accepte les encaissements dans le pays défini par le paramètre d’intégration `emecfCountry` (`BJ` par défaut). L’activation d’un corridor compare le pays du hub de vente à cette valeur ; aucun pays n’est codé en dur. Les corridors dont le hub de vente est hors de ce pays restent bloqués jusqu’à validation d’un connecteur fiscal couvrant leur pays. Les délais et le nombre d’essais de retrait se règlent dans les paramètres d’exploitation.
3. Configurer un budget de soute pour le départ utilisé en recette. Vérifier les sessions de caisse, les moyens de paiement, WhatsApp/SMS, les workers, le scheduler, e-MECeF et les autorisations P501. Pour un corridor international, valider aussi les formalités de passage frontière et les conditions d’encaissement et de retrait.
4. Activer le corridor de recette et effectuer une prise en charge, un scan hors ligne synchronisé, la réception, un retrait par code, une réimpression et le rapprochement du reçu certifié. Désactiver le corridor pour interrompre les nouveaux dépôts et terminer les envois sous garde.
5. Suivre les paiements portant `parcel_reconciliation_required`, les factures Colis en attente, les conflits de scan, les retours à affecter et les incidents ouverts. Un paiement à rapprocher doit être examiné par Finance avant restitution.

Les clients mobiles récupèrent les contrats dans la spécification [OpenAPI](../mintlify/api/openapi.yaml). Le P501 synchronise les types `parcel.load` et `parcel.unload` avec `departure_uuid`, `reference` et `stop_uuid` dans le payload et utilise `local_recorded_at` pour l’heure observée. L’étiquette et le reçu fiscal sont demandés séparément. La recette matérielle doit vérifier le rendu des commandes ESC/POS sur le modèle de terminal déployé.

## Deposit location and routing

A deposit location is a `parcel_hub`: an internal agency hub (`kind=agency`) or a partner point hub (`kind=partner_point`, backed by a unique `kora_point_id`). Activation of a corridor requires structural reachability only: both stops on the same line, origin stop before destination stop. `GET /parcels/data/routing/departures` lists the concrete eligible departures inside `operations.parcelRoutingHorizonDays` (default 30). The public corridor listing only returns corridors with at least one eligible departure.

A partner point whose stop is not served in the correct order by an eligible departure is never proposed and intake is rejected. No implicit transfer to an agency, no substitute hub and no virtual stop is applied; attach the partner hub to a served stop or leave the corridor disabled.

In KORA OPS `/parcels`, the **Corridors & tarifs** tab drives `PUT /parcels/data/corridors` and `POST /parcels/data/corridors/{uuid}/tariffs`, while **Capacité des départs** reads `GET /parcels/data/capacity` and writes `PUT /parcels/data/departures/{uuid}/capacity`. The counter direct-deposit form uses the web endpoint `POST /parcels/data/intake` (permission `parcels.intake`) and returns the generated reference and tracking QR immediately. An internal agency or partner point already attached to a deposit location is withheld from the creation dialog options and rejected server-side; archive a hub before reusing its entity elsewhere.
