## Notifications passager et push FCM

La documentation couvre maintenant la différence entre l’inbox persistante et le push, ainsi que le cycle d’inscription et de renouvellement des tokens FCM par appareil.

### Références API

- **Inscription push** : `PUT /api/v1/auth/devices/{device_uuid}/push-token` associe ou retire le token sur un appareil existant de l’utilisateur authentifié.
- **Inbox passager** : liste paginée, compteur non lu, lecture individuelle et lecture globale.
- **Configuration cliente Firebase** : les valeurs publiques mobiles sont retournées par `GET /api/v1/auth/passenger/firebase-configuration`; les secrets serveur restent privés.
- L’OpenAPI a été régénéré depuis les FormRequests et les annotations Scribe des contrôleurs.

### Guides

- Mise à jour du flux de confiance appareil et de l’inscription FCM.
- Clarification des préférences push et de l’indépendance de l’inbox lorsque le push est indisponible.

</Update>

## Endpoint « Mes voyages » — billets du passager authentifié

Nouvel endpoint `GET /api/v1/tickets` qui liste tous les billets du passager authentifié, tous statuts confondus, avec un contrat enrichi pour l'écran « Mes voyages » de l'app passager.

### Nouveautés

- **`GET /api/v1/tickets`** : liste paginée (15 par page) des billets où `created_by_user_id` ou `payer_user_id` correspond à l'utilisateur connecté
- **Contrat enrichi** (`PassengerTicketResource`) : route (ville origine → destination), date/heure de départ, siège, gare de départ, montant payé, QR code, passager, infos ligne
- **Mappage des statuts** côté API : `issued → confirmed`, `used → completed`, `cancelled/refunded → cancelled`
- **Séparation des ressources** : `PassengerTicketResource` distincte de `TicketResource` existante pour ne pas casser le contrat de `GET /bookings/{uuid}/tickets`

### Documentation

- Nouvelle page de référence : `reference/payments/tickets-list.mdx`
- Endpoint ajouté dans `openapi.yaml`
- Navigation Mintlify mise à jour

</Update>

## Restructuration de la documentation API (KORA-38)

Refonte complète de la documentation API pour suivre le modèle FedaPay : layout API Reference avec playground interactif, exemples multi-langages, et schémas extraits de la codebase.

### API Reference

- **31 pages d'endpoints** créées avec schémas exacts extraits des FormRequests, Resources et contrôleurs
- **15 endpoints Auth** : OTP request/verify, register-complete, login, OAuth token, PIN reset/change, unlock, me, me-update, devices list/revoke, preferences get/update, logout
- **6 endpoints Bus** : cities, lines, line, departures, departure, seats
- **5 endpoints Booking** : quotes, holds, reservation, release-hold, passengers
- **3 endpoints Payments** : initiate, show, confirm (webhook)
- **2 endpoints Health** : health, ping

### Playground interactif

- Playground interactif avec affichage de l'URL complète (`api.url: "full"`)
- Switcher de servers : **Staging** (`staging.koraexpress.app`) et **Production** (`prod.koraexpress.app`)
- Exemples de code en 4 langages : cURL, JavaScript, TypeScript, Dart
- Authentification bearer pré-configurée

### Navigation

- Icônes Lucide sur tous les tabs et groups de la sidebar
- Groups déroulés par défaut dans l'API Reference
- 4 tabs : Démarrage, Guides, API Reference, Sécurité
- Anchor WhatsApp dans la topbar

### Thème

- Couleur primaire : `#1A56DB` (bleu vif)
- Couleur light : `#FCD34D` (jaune doré)
- Couleur dark : `#0F172A` (slate foncé)
- Mode light/dark avec détection système

### Infrastructure

- Script `normalize-mintlify-openapi.php` mis à jour pour générer les servers staging + prod
