# Devis & blocage de sièges

Le mobile sélectionne un résultat de recherche, demande un devis serveur, choisit un siège par passager et par leg, puis crée un blocage de sièges (`hold`). Le prix et l'état de disponibilité restent sous l'autorité du serveur.

## 1. Créer le devis d'itinéraire

```bash
curl -X POST https://staging.koraexpress.app/api/v1/bus/itinerary-quotes \
  -H 'Authorization: Bearer $TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "passenger_count": 2,
    "legs": [
      { "leg_order": 1, "departure_uuid": "departure-leg-1-uuid", "origin_stop_uuid": "origin-stop-uuid", "destination_stop_uuid": "connection-stop-uuid" },
      { "leg_order": 2, "departure_uuid": "departure-leg-2-uuid", "origin_stop_uuid": "connection-stop-uuid-2", "destination_stop_uuid": "destination-stop-uuid" }
    ]
  }'
```

La réponse est enveloppée dans `data` et contient l'UUID du devis, le montant total, la devise, l'expiration, les devis de chaque leg et le détail de tarification dynamique.

### Code promo

Un code promotionnel peut se saisir à deux moments :

- **Au devis** via le champ optionnel `promo_code` — la remise est visible dès le récapitulatif dans `pricing.promotion` et `pricing.promotion_discount_amount`.
- **Sur la réservation** via `PUT /api/v1/bookings/{uuid}/promo-code` — pour une saisie tardive sur l'écran de paiement, sans recréer le devis ni les sièges. Envoyez `null` pour retirer la remise. Voir [Appliquer un code promo](/reference/booking/promo-code).

Un code refusé renvoie `422` sur le champ `promo_code`. Le code n'est consommé qu'au paiement confirmé : un devis, un hold ou une remise appliquée puis abandonnée n'utilise pas de quota. La remise appliquée est déclarée à la certification e-MECeF sur la facture émise après paiement.

## 2. Créer le hold

```bash
curl -X POST https://staging.koraexpress.app/api/v1/bus/itinerary-holds \
  -H 'Authorization: Bearer $TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "itinerary_quote_uuid": "itinerary-quote-uuid",
    "idempotency_key": "hold-device-uuid-attempt-001",
    "passengers": [
      {
        "passenger_index": 0,
        "seat_assignments": [
          { "leg_order": 1, "seat_uuid": "seat-leg-1-passenger-1" },
          { "leg_order": 2, "seat_uuid": "seat-leg-2-passenger-1" }
        ]
      },
      {
        "passenger_index": 1,
        "seat_assignments": [
          { "leg_order": 1, "seat_uuid": "seat-leg-1-passenger-2" },
          { "leg_order": 2, "seat_uuid": "seat-leg-2-passenger-2" }
        ]
      }
    ]
  }'
```

La matrice doit contenir exactement un siège pour chaque couple `passenger_index × leg_order`. Le hold retourne une réservation `held`, son expiration, les segments et le montant serveur.

## Expiration et conflits

| Situation | Réponse | Action mobile |
|---|---:|---|
| Devis expiré | `422` | Rechercher et recréer un devis. |
| Siège pris entre la consultation et le hold | `409` | Recharger les sièges du leg concerné. |
| Matrice passager/leg incomplète | `422` | Corriger les assignations. |
| Rejeu avec la même clé | `201` avec la réservation existante | Réutiliser l'UUID retourné. |
| Abandon du parcours | `204` | Libérer le hold avec l'endpoint prévu. |

<Warning>
  Ne transmettez jamais un `total_amount` calculé par le mobile comme source de vérité. Le serveur calcule et fige le montant depuis le devis d'itinéraire.
</Warning>
