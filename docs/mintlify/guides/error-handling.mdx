L'API KORA BUS utilise une structure d'erreur uniforme. Tous les clients mobiles doivent la parser de manière cohérente.

## Structure d'erreur

```json
{
  "error": {
    "code": "account_locked",
    "message": "Le compte est temporairement bloqué après plusieurs tentatives incorrectes.",
    "locked_until": "2026-08-17T13:00:00.000Z"
  }
}
```

| Champ | Type | Description |
|-------|------|-------------|
| `error.code` | string | Code métier stable (machine-readable) |
| `error.message` | string | Message humain (FR par défaut) |
| `error.*` | mixed | Champs contextuels optionnels (ex: `locked_until`, `challenge`) |

## Codes HTTP

| Code | Sens | Action client |
|------|------|---------------|
| `200` | Succès (GET, PUT) | Parser `data` |
| `201` | Création (POST) | Parser `data` |
| `202` | Accepté (action asynchrone ou OTP requis) | Parser `data` |
| `204` | Succès sans contenu (DELETE) | Pas de body |
| `400` | Requête malformée | Corriger la requête |
| `401` | Non authentifié | Token manquant ou invalide → re-authentifier |
| `403` | Interdit | Permission insuffisante ou action requise (ex: `otp_required`) |
| `404` | Ressource introuvable | UUID invalide ou ressource supprimée |
| `422` | Validation échouée | Parser `error.fields` pour les champs en erreur |
| `423` | Compte verrouillé | Afficher écran de déverrouillage OTP |
| `429` | Rate limit dépassé | Backoff exponentiel, respecter `Retry-After` |
| `500` | Erreur serveur | Retry limité, logger et remonter |
| `503` | Service indisponible | Healthcheck dégradé, réessayer plus tard |

## Codes métier

### Authentification

| Code | HTTP | Description |
|------|------|-------------|
| `invalid_credentials` | 422 | Email ou PIN incorrect |
| `account_locked` | 423 | Compte verrouillé après tentatives |
| `account_suspended` | 403 | Compte suspendu (support requis) |
| `otp_required` | 202 | Nouvel appareil, vérification OTP requise |
| `otp_expired` | 422 | Code OTP expiré |
| `otp_invalid` | 422 | Code OTP incorrect |
| `verification_token_invalid` | 422 | Token de vérification invalide ou expiré |
| `otp_delivery_unavailable` | 503 | Aucun canal (WhatsApp ni email joignable) ne peut délivrer le code — réessayer plus tard |
| `account_exists` | 409 | Compte avec PIN déjà existant pour cet identifiant — passer par la connexion |
| `name_required` | 422 | Nom obligatoire pour une inscription par téléphone créant un nouveau compte |
| `phone_taken` | 422 | Numéro déjà utilisé par un autre compte |
| `email_taken` | 422 | Email déjà utilisé par un autre compte |

### Exemples d'erreurs

<Steps>
  <Step title="Identifiants invalides">

```bash
curl -X POST https://staging.koraexpress.app/api/v1/auth/login \
  -H 'Content-Type: application/json' \
  -d '{ "email": "wrong@korabus.app", "pin": "0000", "device_name": "Test", "platform": "ios", "device_fingerprint": "abc" }'
```

**Réponse (422) :**

```json
{
  "error": {
    "code": "invalid_credentials",
    "message": "Identifiants invalides."
  }
}
```
  </Step>

  <Step title="Compte verrouillé">

```json
{
  "error": {
    "code": "account_locked",
    "message": "Le compte est temporairement bloqué après plusieurs tentatives incorrectes.",
    "locked_until": "2026-08-17T13:30:00.000Z"
  }
}
```

Le client doit afficher un écran de déverrouillage et lancer le flow `otp/request` avec `purpose: "account_unlock"`.
  </Step>

  <Step title="Nouvel appareil détecté">

```json
{
  "data": {
    "requires_otp": true,
    "otp_challenge_uuid": "c5216701-9e2a-4f3b-8c1d-0a4e5f6789ab",
    "purpose": "login_new_device",
    "expires_at": "2026-08-17T13:15:00.000Z"
  }
}
```

Le client doit enchaîner : `otp/request` → `otp/verify` → `login` avec `otp_challenge_uuid` + `verification_token`.
  </Step>

  <Step title="Erreur de validation">

```json
{
  "error": {
    "code": "validation_failed",
    "message": "Les données fournies sont invalides.",
    "fields": {
      "email": ["L'email est obligatoire."],
      "pin": ["Le PIN doit contenir 4 chiffres."]
    }
  }
}
```
  </Step>
</Steps>

## Gestion dans Flutter

<CodeGroup>

```dart Dart
// lib/core/api/kora_error.dart
class KoraApiException implements Exception {
  final String code;
  final String message;
  final int statusCode;
  final Map<String, dynamic>? context;

  KoraApiException({
    required this.code,
    required this.message,
    required this.statusCode,
    this.context,
  });

  factory KoraApiException.fromResponse(Response response) {
    final body = response.data as Map<String, dynamic>;
    final error = body['error'] as Map<String, dynamic>;
    return KoraApiException(
      code: error['code'] as String,
      message: error['message'] as String,
      statusCode: response.statusCode ?? 500,
      context: error,
    );
  }
}

// Usage avec Dio
dio.interceptors.add(InterceptorsWrapper(
  onError: (e, handler) {
    if (e.response != null) {
      final koraError = KoraApiException.fromResponse(e.response!);
      switch (koraError.code) {
        case 'account_locked':
          // Naviguer vers l'écran de déverrouillage
          break;
        case 'otp_required':
          // Naviguer vers le flow OTP
          final challengeUuid = koraError.context?['challenge']?['otp_challenge_uuid'];
          break;
        case 'invalid_credentials':
          // Afficher message d'erreur sur l'écran de login
          break;
      }
    }
    return handler.next(e);
  },
));
```

</CodeGroup>

## Rate limiting

L'API applique des limites par endpoint :

| Throttle | Endpoints | Limite |
|----------|-----------|--------|
| `auth-otp` | `/auth/otp/*` | 5 / minute |
| `auth-login` | `/auth/login`, `/auth/register/complete` | 10 / minute |
| `bus-search` | `/bus/*` | 60 / minute |

### Headers de rate limit

```
X-RateLimit-Limit: 60
X-RateLimit-Remaining: 58
Retry-After: 30  # (uniquement sur 429)
```

### Stratégie de retry

<CodeGroup>

```dart Dart
// Backoff exponentiel avec Dio
dio.interceptors.add(RetryInterceptor(
  dio: dio,
  retries: 3,
  retryDelays: const [
    Duration(seconds: 1),
    Duration(seconds: 2),
    Duration(seconds: 5),
  ],
  retryEvaluator: (error, attempt) {
    return error.response?.statusCode == 429 ||
        error.type == DioExceptionType.connectionTimeout;
  },
));
```
