---
title: Gestion des appareils
description: "Gérez les appareils de confiance KORA BUS : vérification OTP sur un nouvel appareil, tokens Sanctum liés, liste et révocation des devices."
---


KORA BUS gère des appareils de confiance liés au compte. Un nouvel appareil déclenche une vérification OTP. L’appareil est créé après la vérification réussie, puis l’utilisateur peut le lister et le révoquer à tout moment.

## Comment fonctionne la confiance d'appareil

<Steps>
  <Step title="Connexion depuis un nouvel appareil">
    L’application envoie son nom, sa plateforme et son fingerprint à `POST /api/v1/auth/login`. Si le fingerprint est inconnu, l’API répond `202` avec `requires_otp: true` et un challenge. À cette étape, l’appareil n’est pas encore enregistré comme appareil de confiance.
  </Step>
  <Step title="Vérification OTP réussie">
    Après `POST /api/v1/auth/otp/verify`, l’application relance `POST /api/v1/auth/login` avec `otp_challenge_uuid` et `verification_token`. L’API crée alors l’appareil et retourne son UUID avec la session. C’est cet UUID qui permet ensuite d’inscrire un token FCM.
  </Step>
  <Step title="Appareil connu">
    Les connexions suivantes depuis un appareil actif connu se font sans OTP supplémentaire — avec les identifiants et le PIN.
  </Step>
  <Step title="Révocation">
    L'utilisateur peut révoquer un appareil à tout moment. L'appareil révoqué devra refaire un OTP à la prochaine connexion.
  </Step>
</Steps>

## Lister les appareils

```dart
final res = await authDio.get('/api/v1/auth/devices');
final devices = res.data['data'] as List;

for (final d in devices) {
  print('${d['name']} (${d['platform']}) — ${d['status']}');
}
// iPhone 15 Pro (ios) — trusted
// Samsung Galaxy S24 (android) — trusted
```

Voir la référence : [Appareils — Lister](/reference/auth/devices-list).

## Révoquer un appareil

```dart
// Révoquer un appareil spécifique
await authDio.delete('/api/v1/auth/devices/${deviceUuid}');
```

<Warning>
  Révoquer l'**appareil courant** déconnecte immédiatement l'utilisateur. Le token courant est invalidé côté serveur.
</Warning>

## Inscrire le token push après la connexion

Le SDK Firebase côté application mobile crée et renouvelle le token FCM. Après une demande de permission explicite et l’obtention du token, l’application l’envoie à `PUT /api/v1/auth/devices/{device_uuid}/push-token`, en utilisant l’UUID renvoyé par l’authentification. Le serveur n’enregistre donc pas le device à partir de cet endpoint : il ne fait qu’associer ou retirer un token d’un appareil actif appartenant à l’utilisateur.

```dart
await authDio.put('/api/v1/auth/devices/$deviceUuid/push-token', data: {
  'enabled': true,
  'push_token': fcmToken,
});
```

Quand FCM renouvelle le token, renvoyez le nouveau token au même endpoint. Pour le retirer, envoyez `enabled: false`. Voir [Inscrire ou retirer un token push](/reference/auth/devices-push-token) et le [guide des notifications](/guides/notifications).

## Sécurité multi-appareils

- Chaque appareil a son **propre token** Sanctum. Révoquer un appareil n'affecte pas les autres.
- Le `device_fingerprint` doit être **unique et stable** par appareil — utilisez un identifiant matériel ou un UUID persistant côté app.
- Chaque installation peut enregistrer son propre token FCM après opt-in. Le token est supprimé quand l’utilisateur désactive les push ou à la révocation de l’appareil.
