# Récupérer une réservation

Récupère l'état serveur complet d'une réservation via `ReservationResource`. À utiliser après une perte de session mobile pour reprendre le parcours sans reconstruire l'état local.

## Paramètres

<ParamField path="reservation_uuid" type="UUID" required>
  UUID de la réservation (route model binding sur colonne `uuid`).
</ParamField>

```bash cURL

  -H 'Authorization: Bearer 1|aBcDeFgHiJkLmNoPqRsTuVwXyZ0123456789abcdef' \
```

## Codes de réponse

| Code | Description |
|------|-------------|
| `200` | Réservation retournée. |
| `401` | Token absent ou invalide. |
| `403` | Réservation appartenant à un autre utilisateur (policy `view`). |
| `404` | Réservation introuvable. |

<Info>
  Le mobile ne doit **jamais** reconstruire la réservation depuis son état local. La réponse contient le statut, `expires_at`, les segments, les voyageurs et le montant serveur.
</Info>

## Champs de remise

| Champ | Description |
|-------|-------------|
| `subtotal_amount` | Sous-total avant remise promo et remise groupe (issu du snapshot tarifaire). |
| `promotion_discount_amount` | Montant de la remise promo appliquée (`0` si aucune). |
| `promotion` | Promotion appliquée (`uuid`, `code`, `name`, `benefit_type`, `benefit_value`, `discount_amount`) ou `null`. |

La promotion peut provenir du devis (`promo_code` à la création) ou d'une saisie tardive via [PUT /api/v1/bookings/{uuid}/promo-code](/reference/booking/promo-code). La remise est ensuite déclarée à la certification e-MECeF sur la facture.
