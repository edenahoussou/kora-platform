---
title: Lister ses colis
description: "GET /api/v1/parcels retourne une liste paginée de 25 colis où le titulaire est expéditeur ou destinataire vérifié."
api: GET /api/v1/parcels
---

Liste paginée de 25 colis. Les données du destinataire ne sont visibles qu’après un OTP consommé sur le téléphone courant. La réponse ne contient pas `timeline` : elle est chargée uniquement lorsque la relation `events` est demandée sur le détail.

## Requête

<RequestExample>

```bash cURL
curl -X GET 'https://staging.koraexpress.app/api/v1/parcels' \
  -H 'Authorization: Bearer $KORA_TOKEN' \
  -H 'Accept: application/json'
```

```dart Dart
final response = await dio.get('/api/v1/parcels', options: Options(headers: {
  'Authorization': 'Bearer $token',
}));
final parcels = response.data['data'] as List;
```

</RequestExample>

## Règles

- Pagination fixe à 25 éléments ; `meta.total` donne le nombre de colis accessibles.
- Un colis où le titulaire n’est ni expéditeur ni destinataire vérifié n’apparaît pas.
- `timeline` n’est pas incluse dans la liste ; utilisez `GET /parcels/{uuid}` ou le suivi public.
- Aucun code de retrait, hash, secret ou identifiant numérique interne n’est exposé.

## Codes de réponse

| Code | Corps / message |
|---|---|
| `200` | Liste paginée. |
| `401` | `{"message":"Unauthenticated."}` |
| `403` | `{"message":"This action is unauthorized."}` |

## Sécurité

`Authorization: Bearer <token Sanctum>` requis. Le titulaire doit posséder `parcels.customer`. Un tiers reçoit `404`, jamais l’existence du colis.
