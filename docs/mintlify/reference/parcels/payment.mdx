---
title: Consulter un paiement Colis
description: "GET /api/v1/parcels/{parcel_uuid}/payments/{uuid} retourne l’état et la prochaine action du paiement."
api: GET /api/v1/parcels/{parcel_uuid}/payments/{uuid}
---

Consulte l’état d’une tentative de paiement et l’état de vérification. Réservé à l’expéditeur propriétaire. Retourne le montant, le moyen, le financement Wallet et `next_action`, sans payload prestataire complet.

## Paramètres

<ParamField path="parcel_uuid" type="UUID" required>
  UUID public du colis.
</ParamField>

<ParamField path="uuid" type="UUID" required>
  UUID public du paiement.
</ParamField>

## Requête

<RequestExample>

```bash cURL
curl -X GET 'https://staging.koraexpress.app/api/v1/parcels/00000000-0000-4000-8000-000000000010/payments/00000000-0000-4000-8000-000000000030' \
  -H 'Authorization: Bearer $KORA_TOKEN' \
  -H 'Accept: application/json'
```

```dart Dart

  'Authorization': 'Bearer $token',
```

</RequestExample>

## Règles

- Le paiement doit appartenir au colis et le colis au propriétaire ; sinon `404`.
- `provider_reference` et `provider_transaction_id` peuvent être `null` pour Wallet.
- `wallet_funding` n’est présent que pour un financement Wallet.
- Aucun payload prestataire complet, aucune clé et aucun secret ne sont exposés.

## Codes de réponse

| Code | Corps / message |
|---|---|
| `200` | État du paiement. |
| `401` | `{"message":"Unauthenticated."}` |
| `403` | `{"message":"This action is unauthorized."}` |
| `404` | `{"message":"Not Found"}` |

## Sécurité

`Authorization: Bearer <token Sanctum>` requis. Réservé à l’expéditeur propriétaire. Un tiers reçoit `404`.
