---
title: Vérifier un paiement Colis
description: "POST /api/v1/parcels/{parcel_uuid}/payments/{payment_uuid}/verify vérifie la transaction auprès du prestataire."
api: POST /api/v1/parcels/{parcel_uuid}/payments/{payment_uuid}/verify
---

Vérifie la transaction auprès du prestataire et met à jour l’état du paiement. Réservé à l’expéditeur propriétaire. Si le prestataire n’est pas supporté, l’état courant est retourné sans erreur. `transaction_id` est optionnel et borné à 128 caractères.

## Paramètres

<ParamField path="parcel_uuid" type="UUID" required>
  UUID public du colis.
</ParamField>

<ParamField path="payment_uuid" type="UUID" required>
  UUID public du paiement.
</ParamField>

<ParamField body="transaction_id" type="string">
  Identifiant de transaction prestataire, maximum 128 caractères.
</ParamField>

## Règles

- `transaction_id` est optionnel : un paiement Wallet confirmé peut être vérifié avec `{}`.
- Un `transaction_id` de plus de 128 caractères renvoie `422`.
- Un prestataire non supporté retourne la ressource courante sans erreur.
- La vérification ne crée pas un second paiement et ne modifie pas l’idempotence.

## Codes de réponse

| Code | Corps / message |
|---|---|
| `200` | Paiement vérifié ou état courant retourné. |
| `401` | `{"message":"Unauthenticated."}` |
| `403` | `{"message":"This action is unauthorized."}` |
| `404` | `{"message":"Not Found"}` |
| `422` | `{"message":"Le champ transaction id ne doit pas dépasser 128 caractères.","errors":{"transaction_id":["Le champ transaction id ne doit pas dépasser 128 caractères."]}}` |
| `429` | `{"message":"Too Many Attempts."}` |

## Sécurité

`Authorization: Bearer <token Sanctum>` requis. Réservé à l’expéditeur propriétaire. Un tiers reçoit `404`. Limité à 10 requêtes par minute.
