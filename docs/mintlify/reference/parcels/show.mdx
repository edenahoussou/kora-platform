---
title: Consulter un colis
description: "GET /api/v1/parcels/{uuid} retourne le détail métier d’un colis accessible au titulaire ou au destinataire vérifié."
api: GET /api/v1/parcels/{uuid}
---

Détail d’un colis : inspection, devis, flags d’action et état de remise. Le code de retrait, les hashes et les secrets ne sont jamais retournés. Un tiers reçoit `404`.

## Paramètres

<ParamField path="uuid" type="UUID" required>
  UUID public du colis.
</ParamField>

## Requête

<RequestExample>

```bash cURL
curl -X GET 'https://staging.koraexpress.app/api/v1/parcels/00000000-0000-4000-8000-000000000010' \
  -H 'Authorization: Bearer $KORA_TOKEN' \
  -H 'Accept: application/json'
```

```dart Dart
final response = await dio.get('/api/v1/parcels/$uuid', options: Options(headers: {
  'Authorization': 'Bearer $token',
}));
final parcel = response.data['data'];
```

</RequestExample>

## Règles

- `timeline` n’est présent que si la relation `events` est chargée ; les réponses client show/list ne la chargent pas par défaut.
- Les flags `can_*` indiquent les actions autorisées à l’instant du appel ; ils ne remplacent pas le contrôle serveur.
- `quote` reflète le dernier devis pesé ; il peut être `null` avant pesée.
- `inspection` expose uniquement l’état, la catégorie, le motif de refus et le hub, jamais l’agent OPS.

## Codes de réponse

| Code | Corps / message |
|---|---|
| `200` | Détail du colis. |
| `401` | `{"message":"Unauthenticated."}` |
| `403` | `{"message":"This action is unauthorized."}` |
| `404` | `{"message":"Not Found"}` |

## Sécurité

`Authorization: Bearer <token Sanctum>` requis. Le titulaire doit posséder `parcels.customer`. Un tiers reçoit `404`, jamais l’existence du colis. En local avec `APP_DEBUG=true`, Laravel peut ajouter `exception`, `file`, `line` et `trace` à une erreur `404`. Ce n’est pas le contrat public : la production doit garder `APP_DEBUG=false` et ne renvoyer que `message: Not Found`.
