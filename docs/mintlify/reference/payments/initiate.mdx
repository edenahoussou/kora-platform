---
title: Initier un paiement
description: "POST /api/v1/payments/initiate : initier un paiement Mobile Money (FedaPay, MTN MoMo) pour une réservation held, avec clé d'idempotence unique."
api: POST /api/v1/payments/initiate
---

Initie un paiement Mobile Money pour une réservation au statut `held`. Au Bénin, KORA facture en `XOF` et FedaPay utilise `XOF`. Le sandbox public MTN impose `EUR` pour les appels de test; cela ne constitue pas une conversion de devise métier. En production, MTN utilise la devise du compte provisionné, configurée séparément. L'idempotence est garantie par `idempotency_key`.

## Paramètres

<ParamField body="reservation_uuid" type="UUID" required>
  UUID de la réservation à payer (doit exister dans `reservations`).
</ParamField>

<ParamField body="method" type="string" required>
  `mobile_money` est la seule méthode actuellement activée dans le parcours passager. `wallet` est reconnu par le contrat mais reste désactivé jusqu'à l'activation du ledger.
</ParamField>

<ParamField body="provider" type="string" required>
  Provider retourné par `GET /api/v1/payments/methods` (`fedapay` ou `mtn_momo`). Max 64.
</ParamField>

<ParamField body="idempotency_key" type="string" required>
  Clé d'idempotence unique par tentative. Max 255.
</ParamField>

<ParamField body="phone" type="string">
  Téléphone Mobile Money (max 32). Requis si `method=mobile_money`.
</ParamField>

<ParamField body="mobile_money_network" type="string" required>
  Réseau utilisé : `mtn_momo`, `moov_flooz` ou `celtiis_cash`. Le provider doit supporter ce réseau.
</ParamField>

<ParamField body="wallet_amount" type="integer">
  Montant prévu sur le Wallet dans le contrat de paiement mixte. Le Wallet reste désactivé tant que le ledger n'est pas activé.
</ParamField>

## Réponse

<ResponseField name="data" type="Payment" required>
  <ResponseField name="uuid" type="UUID" required>UUID du paiement.</ResponseField>
  <ResponseField name="status" type="string" required>`pending`, `confirmed`, `failed`, `cancelled`, ou `refunded`.</ResponseField>
  <ResponseField name="amount" type="integer" required>Montant facturé au passager (en `currency`).</ResponseField>
  <ResponseField name="currency" type="string" required>Devise KORA. Toujours `XOF` au MVP.</ResponseField>
  <ResponseField name="method" type="string" required>`mobile_money`.</ResponseField>
  <ResponseField name="provider" type="string" required>Provider utilisé (`fedapay` ou `mtn_momo`).</ResponseField>
  <ResponseField name="mobile_money_network" type="string" required>Réseau sélectionné (`mtn_momo`, `moov_flooz`, `celtiis_cash`).</ResponseField>
  <ResponseField name="provider_currency" type="string">Devise envoyée au provider. Peut différer de `currency` (ex: `EUR` en sandbox MTN).</ResponseField>
  <ResponseField name="provider_amount" type="integer">Montant envoyé au provider (en `provider_currency`).</ResponseField>
  <ResponseField name="provider_reference" type="string">Référence provider ou `null` si non encore assignée.</ResponseField>
  <ResponseField name="provider_transaction_id" type="string">ID technique provider ou `null`.</ResponseField>
  <ResponseField name="payer_phone" type="string">Téléphone du payeur tel que fourni.</ResponseField>
  <ResponseField name="confirmed_at" type="string">Date de confirmation (ISO 8601) ou `null`.</ResponseField>
  <ResponseField name="last_verified_at" type="string">Dernière vérification serveur (ISO 8601) ou `null`.</ResponseField>
  <ResponseField name="next_action" type="string" required>Action attendue côté mobile : `verify` (pending), `wait_for_tickets` (confirmed, billets en cours), `show_tickets` (confirmed, billets émis), ou `retry` (failed/cancelled).</ResponseField>
  <ResponseField name="failure" type="object">Présent uniquement si le paiement a échoué. Contient `code` et `message`.</ResponseField>
  <ResponseField name="expires_at" type="string">Expiration du hold de la réservation (ISO 8601) ou `null`.</ResponseField>
  <ResponseField name="polling_interval_seconds" type="integer" required>Toujours `10`.</ResponseField>
</ResponseField>

## Codes de réponse

| Code | Description |
|------|-------------|
| `201` | Paiement initié. |
| `200` | Replay idempotent — paiement déjà existant. |
| `401` | Token absent ou invalide. |
| `403` | Utilisateur non autorisé à payer cette réservation. |
| `422` | Réservation non `held`, méthode invalide, réservation expirée, ou validation échouée. |

<Warning>
  Le paiement est accepté **uniquement** tant que le hold est valide. Après initiation, utilisez `POST /payments/{uuid}/verify` pour demander une vérification serveur explicite ; le polling GET reste utile pour rafraîchir l'état. Une même clé réutilisée sur une autre réservation ou avec un payload différent est rejetée.
</Warning>
