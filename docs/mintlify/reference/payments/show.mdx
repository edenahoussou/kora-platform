# Consulter un paiement

Retourne le statut courant d'un paiement via `PaymentResource`. La relation `reservation` est **toujours chargée** dans cet endpoint (`loadMissing(['reservation.departure'])`). À appeler après `POST /payments/{uuid}/verify` pour rafraîchir l'état jusqu'à l'émission des billets.

## Paramètres

<ParamField path="payment_uuid" type="UUID" required>
  UUID du paiement (route model binding sur colonne `uuid`).
</ParamField>

## Statuts de paiement

| Statut | Description |
|--------|-------------|
| `pending` | Paiement initié, en attente de confirmation provider |
| `confirmed` | Paiement confirmé par le provider (webhook) |
| `failed` | Paiement échoué ou réservation expirée avant confirmation |
| `cancelled` | Paiement annulé |
| `refunded` | Paiement remboursé |

## Codes de réponse

| Code | Description |
|------|-------------|
| `200` | Paiement retourné. |
| `401` | Token absent ou invalide. |
| `403` | Paiement appartenant à un autre utilisateur. |
| `404` | Paiement introuvable. |

<Info>
  Appelez `POST /payments/{uuid}/verify`, puis rafraîchissez avec ce GET toutes les `polling_interval_seconds` (10s). Évitez un polling trop agressif pour respecter le rate limit.
</Info>
