# Annuler un paiement

Annule un paiement au statut `pending`. Seul le propriétaire de la réservation peut annuler. L'annulation est définitive : le passager doit réinitier un nouveau paiement s'il veut reprendre.

<Warning>
  Un paiement déjà `confirmed`, `failed`, `cancelled` ou `refunded` ne peut **pas** être annulé. L'API retourne `422` avec une erreur de validation.
</Warning>

## Paramètres

<ParamField path="payment_uuid" type="UUID" required>
  UUID du paiement (route model binding sur colonne `uuid`).
</ParamField>

Aucun corps de requête.

## Réponse

La réponse reprend `PaymentResource` avec `status=cancelled` et `next_action=retry`.

<ResponseField name="data" type="Payment" required>
  <ResponseField name="uuid" type="UUID" required>UUID du paiement.</ResponseField>
  <ResponseField name="status" type="string" required>Toujours `cancelled` après annulation.</ResponseField>
  <ResponseField name="next_action" type="string" required>Toujours `retry`.</ResponseField>
  <ResponseField name="reservation" type="object" required>La réservation reste au statut qu'elle avait avant le paiement (`held` en général).</ResponseField>
</ResponseField>

## Codes de réponse

| Code | Description |
|------|-------------|
| `200` | Paiement annulé avec succès. |
| `401` | Token absent ou invalide. |
| `403` | Le paiement appartient à un autre passager. |
| `404` | Paiement introuvable. |
| `422` | Le paiement n'est pas au statut `pending` — impossible d'annuler. |

<Info>
  L'annulation est **locale uniquement**. KORA ne notifie pas le provider. Si le provider a déjà débité le passager, le remboursement doit être traité manuellement via le dashboard provider.
</Info>
