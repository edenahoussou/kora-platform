# Confirmer (webhook)

`POST /api/v1/payments/{payment_uuid}/confirm`

Endpoint appelé par le **provider de paiement** (Mobile Money, carte) pour confirmer ou échouer un paiement. Cet endpoint est **public** (`@unauthenticated`) — la sécurité repose sur l'isolation réseau et/ou une signature provider (roadmap).

```bash
curl -X POST https://api.korabus.app/api/v1/payments/9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb80/confirm \
  -H 'Content-Type: application/json' \
  -d '{
    "status": "success",
    "provider_reference": "MM-98270341",
    "provider_payload": { "transaction_id": "TXN-12345", "amount": 12500 }
  }'
```

```javascript
// Côté serveur backend (webhook handler) — pas côté app mobile
const res = await fetch(`https://api.korabus.app/api/v1/payments/${paymentUuid}/confirm`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ status: 'success', provider_reference: 'MM-98270341', provider_payload: { transaction_id: 'TXN-12345' } }),
});
```

```typescript
const res = await fetch(`https://api.korabus.app/api/v1/payments/${paymentUuid}/confirm`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ status: 'success', provider_reference, provider_payload } satisfies PaymentConfirmRequest),
});
```

```dart
// Côté serveur backend uniquement — pas appelé depuis l'app mobile
final res = await dio.post('/api/v1/payments/9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb80/confirm', data: {
  'status': 'success',
  'provider_reference': 'MM-98270341',
  'provider_payload': { 'transaction_id': 'TXN-12345' },
});
```

**Réponse (200) :**

```json
{
  "status": "confirmed",
  "payment_uuid": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb80",
  "reservation_uuid": "9b1deb4d-3b7d-4bad-9bdd-2b0d7b3dcb70",
  "reservation_status": "paid"
}
```

### Paramètres

| Champ | Type | Requis | Description |
|-------|------|--------|-------------|
| `payment_uuid` | UUID (path) | ✅ | UUID du paiement. |
| `status` | string | ✅ | `success`, `confirmed`, ou `failed`. |
| `provider_reference` | string | ❌ | Référence provider (ex: `MM-98270341`). |
| `provider_payload` | object | ❌ | Payload brut du provider pour audit. |

### Codes de réponse

| Code | Description |
|------|-------------|
| `200` | Paiement confirmé ou échoué — statut retourné. |
| `422` | `status` invalide ou validation échouée. |
| `404` | Paiement introuvable. |

<Warning>
  Si le webhook arrive **après l'expiration** du hold, le backend conserve la réservation à `expired`, libère les segments et marque le paiement `failed` avec `provider_payload.rejection_reason = reservation_expired`. Une réservation expirée n'est **jamais** réactivée.
</Warning>

<Note>
  **Sécurité** : Cet endpoint est public. Une signature HMAC provider est prévue en roadmap pour authentifier les webhooks. En attendant, l'isolation réseau (VPN, IP allowlist) protège l'endpoint en production.
</Note>

<Info>
  Le `provider_payload` est stocké tel quel pour audit et débogage. Il ne doit pas contenir de données sensibles (PIN, CVV).
</Info>
