# Connexion

Authentifie un passager avec email + PIN. Si l'appareil est inconnu, l'API retourne `202` avec un challenge OTP au lieu d'une session. L'app mobile doit alors compléter le flux OTP (`otp/verify` puis rappeler `login` avec `otp_challenge_uuid` + `verification_token`).

## Paramètres

<ParamField body="email" type="string" required>
  Email du passager (format RFC, max 255).
</ParamField>

<ParamField body="pin" type="string" required>
  PIN à 4 chiffres.
</ParamField>

<ParamField body="device_name" type="string" required>
  Nom de l'appareil (max 120).
</ParamField>

<ParamField body="platform" type="string" required>
  `android`, `ios`, `web`, ou `unknown`.
</ParamField>

<ParamField body="device_fingerprint" type="string" required>
  Empreinte unique de l'appareil (min 16, max 255).
</ParamField>

<ParamField body="push_token" type="string">
  Token push (FCM/APNs) (max 512).
</ParamField>

<ParamField body="otp_challenge_uuid" type="UUID">
  Requis si `verification_token` présent. UUID du challenge OTP vérifié (purpose: `login_new_device`).
</ParamField>

<ParamField body="verification_token" type="string">
  Requis si `otp_challenge_uuid` présent. Token retourné par `otp/verify` (64 caractères).
</ParamField>

## Réponse (200 — session)

<ResponseField name="data" type="object" required>
  <ResponseField name="token" type="string" required>Token Sanctum (Bearer).</ResponseField>
  <ResponseField name="token_type" type="string" required>Toujours `Bearer`.</ResponseField>
  <ResponseField name="expires_at" type="string">Expiration (ISO 8601) ou `null`.</ResponseField>
  <ResponseField name="user" type="object" required>Profil utilisateur.</ResponseField>
  <ResponseField name="device" type="object" required>Appareil enregistré.</ResponseField>
</ResponseField>

## Réponse (202 — OTP requis)

<ResponseField name="data" type="object" required>
  <ResponseField name="requires_otp" type="boolean" required>Toujours `true`.</ResponseField>
  <ResponseField name="otp_challenge_uuid" type="UUID" required>UUID du challenge à vérifier.</ResponseField>
  <ResponseField name="purpose" type="string" required>Toujours `login_new_device`.</ResponseField>
  <ResponseField name="expires_at" type="string" required>Expiration du challenge (ISO 8601).</ResponseField>
</ResponseField>

## Codes de réponse

| Code | Description |
|------|-------------|
| `200` | Session émise. |
| `202` | OTP requis pour nouveau device. |
| `403` | `account_suspended`. |
| `422` | `invalid_credentials` ou validation échouée. |
| `423` | `account_locked` (trop de tentatives PIN). |
| `429` | Rate limit `auth-login` dépassé (5/min). |
