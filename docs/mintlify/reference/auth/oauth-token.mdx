# OAuth sociale

Les passagers peuvent créer un compte ou se connecter via **Google**, **Facebook** ou **TikTok** sans OTP. L'app mobile authentifie via le SDK natif, récupère un access token, et l'échange contre une session KORA.

## Paramètres

<ParamField body="provider" type="string" required>
  Provider OAuth : `google`, `facebook`, ou `tiktok`.
</ParamField>

<ParamField body="provider_token" type="string" required>
  Access token du provider (obtenu via le SDK natif, max 4096).
</ParamField>

<ParamField body="device_name" type="string" required>
  Nom de l'appareil (max 120).
</ParamField>

<ParamField body="platform" type="string" required>
  `android`, `ios`, `web`, ou `unknown`.
</ParamField>

<ParamField body="device_fingerprint" type="string" required>
  Empreinte unique de l'appareil (min 16, max 255).
</ParamField>

<ParamField body="push_token" type="string">
  Token push (FCM/APNs) (max 512).
</ParamField>

## Providers supportés

| Provider | Valeur `provider` | SDK Flutter |
|----------|-------------------|------------|
| Google | `google` | `google_sign_in` |
| Facebook | `facebook` | `flutter_facebook_auth` |
| TikTok | `tiktok` | `tiktok_login` |

## Codes de réponse

| Code | Description |
|------|-------------|
| `201` | Nouvel utilisateur créé — token émis. |
| `200` | Utilisateur existant connecté — token émis. |
| `403` | `account_suspended`. |
| `422` | `invalid_oauth_token`, `email_required`, ou validation échouée. |
| `429` | Rate limit `auth-login` dépassé (5/min). |
