# OAuth sociale

KORA BUS permet aux passagers de créer un compte ou de se connecter via **Google**, **Facebook** ou **TikTok**, sans saisir d'email ni de code OTP. Ce flow utilise les SDK natifs des providers.

## Échanger un jeton provider

`POST /api/v1/auth/oauth/token`

L'app mobile authentifie l'utilisateur via le SDK natif du provider, récupère un access token, et l'envoie à l'API KORA. Le backend valide le jeton via Socialite, retrouve ou crée le compte, lie le compte social, télécharge l'avatar et émet un token Sanctum.

```bash
curl -X POST https://api.korabus.app/api/v1/auth/oauth/token \
  -H 'Content-Type: application/json' \
  -d '{
    "provider": "google",
    "provider_token": "ya29.a0AfH6SMB...",
    "device_name": "Samsung Galaxy S24",
    "platform": "android",
    "device_fingerprint": "f6e5d4c3b2a1a1a1a1a1a1a1"
  }'
```

**Réponse (200 — utilisateur existant) :** Même structure, statut `200`.

**Réponse (422 — jeton invalide) :**

```json
{ "error": { "code": "invalid_oauth_token", "message": "Le jeton OAuth fourni n'est pas valide ou a expiré." } }
```

**Réponse (422 — email manquant) :**

```json
{ "error": { "code": "email_required", "message": "Le fournisseur OAuth n'a pas retourné d'adresse email. Un email est obligatoire." } }
```

**Réponse (403 — compte suspendu) :**

```json
{ "error": { "code": "account_suspended", "message": "Le compte est suspendu. Contactez le support." } }
```

### Paramètres

| Champ | Type | Requis | Description |
|-------|------|--------|-------------|
| `provider` | string | ✅ | `google`, `facebook`, ou `tiktok`. |
| `provider_token` | string | ✅ | Access token du provider (SDK natif). |
| `device_name` | string | ✅ | Nom de l'appareil. |
| `platform` | string | ✅ | `ios` ou `android`. |
| `device_fingerprint` | string | ✅ | Empreinte unique de l'appareil. |

### Codes de réponse

| Code | Description |
|------|-------------|
| `201` | Nouvel utilisateur créé — token émis. |
| `200` | Utilisateur existant connecté — token émis. |
| `403` | `account_suspended`. |
| `422` | `invalid_oauth_token`, `email_required`, ou validation échouée. |
| `429` | Rate limit `auth-login` dépassé. |

## Providers supportés

| Provider | Valeur `provider` | SDK Flutter recommandé |
|----------|-------------------|------------------------|
| Google | `google` | `google_sign_in` |
| Facebook | `facebook` | `flutter_facebook_auth` |
| TikTok | `tiktok` | `tiktok_login` |

## Comportement de liaison de comptes

- **Nouvel utilisateur** : un compte est créé avec le rôle `passenger`, l'email est marqué vérifié, l'avatar est téléchargé.
- **Email existant** : le compte social est **lié** au compte KORA existant (aucun doublon).
- **Compte social déjà lié** : l'utilisateur est connecté directement.
- **Compte verrouillé** : la connexion OAuth déverrouille automatiquement le compte.
- **Compte suspendu** : connexion refusée avec `403 account_suspended`.

<Warning>
  **Providers sans email** : TikTok ne retourne pas toujours d'email. L'API refuse la création avec `422 email_required`. L'utilisateur doit utiliser un autre provider ou s'inscrire par email.
</Warning>

<Info>
  L'avatar du provider est automatiquement téléchargé et stocké via **Spatie Media Library**, exposé dans `avatar_url`.
</Info>
