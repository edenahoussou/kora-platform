# Envoyer une réservation en assistance

Transforme la réservation existante : les sièges et le crédit entreprise sont libérés, les segments passent en `requested`, et le dossier entre dans la file de l'agence choisie avec le statut `pending`. Rejouer la même `idempotency_key` retourne le dossier existant (`200`) sans créer de doublon.

## Paramètres

<ParamField path="reservation_uuid" type="UUID" required>
  UUID de la réservation (route model binding sur colonne `uuid`).
</ParamField>

<ParamField body="agency_uuid" type="UUID" required>
  UUID de l'agence choisie (issue de `GET /api/v1/assisted-bookings/agencies`).
</ParamField>

<ParamField body="channel" type="string" required>
  Canal de contact initial : `call` ou `whatsapp`.
</ParamField>

<ParamField body="contact_name" type="string" required>
  Prénom du contact présenté à l'agence (max 120 caractères).
</ParamField>

<ParamField body="contact_phone" type="string" required>
  Téléphone du contact au format international (ex. `+2290197000000`).
</ParamField>

<ParamField body="idempotency_key" type="string" required>
  Clé d'idempotence générée par le client.
</ParamField>

## Codes de réponse

| Code | Description |
|------|-------------|
| `201` | Dossier d'assistance créé. |
| `200` | Rejeu idempotent : dossier existant retourné. |
| `401` | Token absent ou invalide. |
| `403` | Réservation appartenant à un autre utilisateur. |
| `422` | Réservation non éligible (statut, expiration) ou payload invalide. |

<Warning>
  Pendant l'attente, ni les sièges ni le crédit entreprise ne sont bloqués. La `reference` (`KBR-XXXXXXXX`) est affichable dans WhatsApp mais ne constitue jamais une autorisation.
</Warning>
